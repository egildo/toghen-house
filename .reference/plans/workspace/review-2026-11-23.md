# Toghen review, 23 November 2026

## What I reviewed, and how

- **Which code.** I reviewed the eight live Codeberg checkouts in `/Volumes/dev/Codeberg/Toghen`: house, lib, postcss, query, ui, figma, skills and gosfuig. I left out the frozen monorepo this session opened in.
- **The gate.** I ran each repository's own gate: `pnpm check` for the code packages, and the purity script for house and skills.
- **The reviewers.** Seven reviewers read the code against its own docs, the constitution and the W3C specs. Each reviewer proved every finding with a small probe, or by quoting the lines that show it. The probes are in the scratchpad, under `review-*`.
- **How I checked the reviewers.** I re-ran the heaviest claims myself: the lib merge, the paint binding, the gray pin, the FigCraft library runs, the skills install text, the consumer name and the tooltip escaping.
- **Nothing changed.** No repository was changed. Every `git status` is as it was before the review. The only exception was already there: house has one untracked plan.

## The ones that matter most

1. **Figma, FigCraft library mode is broken headless.**
   - With `--figcraft-file` and `--library`, every run fails against figcraft-cli 0.18.1, the version installed here.
   - The cause: the command line finds tabs by the `path` that `doc.list` returns. FigCraft leaves `path` out for calls made through MCP, and headless runs are made that way.
   - What you see: an existing library gives "FigCraft did not open …". A new library is published and saved, then reported unsaved, and the target is left unsaved. Every later run then fails.
   - Why the tests pass: the fake FigCraft returns `path`.
   - Where: `cli/figcraft.ts:302-314, 379`, and `cli/run.ts:362, 430`.
   - Run end to end in the scratchpad.
2. **Figma, a binding through the executor draws the old colour.**
   - `bindPaintColor` (`main/engines/operationExecutor.ts:165-180`) binds the node's existing paint.
   - Measured behaviour §8 says Figma then draws the colour that paint carries, not the variable's.
   - The field writer already works around this (`main/components/fieldWriter.ts:136`, with the comment "Measured: …"). The executor path, used by Apply's bindings and the scaffold, does not.
3. **Figma screen, script injection through the error tooltip.**
   - `ui/components/status-bar.js:33` puts the error message in `title="…"` through `escHtml`, which does not escape `"`. `escAttr` exists, one function below it.
   - A file name or token name with a quote in it can add an `onmouseover` handler. That handler runs in the plugin window, which can send any command to the main thread.
4. **Lib, a context's colour keeps the base colour's alpha and hex.**
   - Example: the base is white at alpha 0.5. The dark context gives `{colorSpace, components:[0,0,0]}`. Dark then resolves to black, still with alpha 0.5 and `hex: '#ffffff'`. Interpolated into a string it reads `1px solid #ffffff80`, which is white.
   - This is the key-by-key merge (`src/resolver/resolver.ts:86-109`). The merge is recorded and deliberate (lib decisions, "What the resolver does with a token").
   - The docs disagree with each other about it: `specs.md` says "the last occurrence wins, so the report changes nothing". The W3C Resolver says the same.
   - Two things make it bite:
     - `hex`, which W3C makes a fallback, is what gets spelled when a structured colour is interpolated (`src/core/alias.ts:389`, `src/utils/css-color.ts:287`).
     - W3C's `alpha` defaults to 1 when it is omitted, and the merge ignores that default.
   - This needs your ruling: replace a `$value` whole, or keep merging but treat a colour as one value.
5. **Figma, a set update that fails partway gets no receipts.**
   - A set or artboard update that fails partway stamps nothing for the writes it already made, and it keeps the old fingerprint (`main/components/update.ts:255`, `run.ts:166-169, 239`).
   - What follows:
     - `--skip-unchanged` reports a half-written set as "unchanged, not read".
     - A full run reports Toghen's own writes as drift and never repairs them without `--overwrite-drift`.
6. **Figma, prune was scoped on a false premise.**
   - The prune spec assumes "the variable sync already removes a variable whose token is gone". It does not.
   - A removed token's variable or style stays in the file with no message, even with `allowBreaking`. A `--prune` check in CI then passes with it there.
   - The decisions list orphan variables as an open question, so the gap is known. The prune spec's assumption is not.
7. **Skills point at the past.**
   - **The install line.** It is `marketplace add egildo/Toghen`, the frozen private monorepo, at plugin 0.5.0. The live marketplace is `egildo/toghen-skills`.
   - **The setup.** It still says figma is private: link a checkout, install lib and postcss by git URL, build at the monorepo root.
   - **The version pins.** They are figma 0.1.10 and FigCraft 0.10.0, with "figcraft-cli 0.8.0 or later". In fact figma before 0.1.16 stops every headless run against figcraft-cli 0.15.1, and FigCraft is now 0.18.1.
   - The re-check rule from the constitution was not run after these releases.
8. **Purity, two names in tracked files.**
   - `figma/decisions.md:1725` names a downstream project by its name. This line came with the last commit.
   - `figma/.reference/plans/plan-2026-10-22-figcraft-components.md:96, 100` names another.
   - The check passes because neither name is in the names file.
9. **Postcss, one unspellable member drops the whole mixin, silently.**
   - Example: a group with a colour and a gradient. `@mixin --card` is not written at all, with no warning, even under `onUnresolved: 'throw'` (`src/index.ts:1399-1405, 1471-1503`).
   - `reference.md` admits "left out with no message". `specs.md` says the plugin reports it.
10. **Postcss, `registerProperties` breaks `light-dark()` switching.**

## Lib

The alias engine, `css-math` and strict modes held under probing. The packaging is right.

1. **The merge rule** is item 4 of the list above.
2. **`color-mix` at 0%, with a translucent first colour, gives channels divided by alpha.**
   - Example: `color-mix(in srgb, rgb(255 0 0 / .5) 100%, blue)` gives components `[2,0,0]`.
   - The cause is culori's premultiplied interpolation at t=0 (`src/utils/css-color.ts:212`).
3. **Overrides beside a `$ref` in `resolutionOrder` are half applied.**
   - Example: `{ $ref: '#/modifiers/theme', default: 'dark' }`.
   - `resolve()` applies the override. Mode names, `getModifiers`, the sum build and the chain index ignore it, so `valueAt` and `resolve` disagree.
   - Where: `resolver.ts:549-558, 713-728`.
4. **Mode names are case-sensitive where the resolver's input is not.**
   - `{Theme:'dark', …}` silently builds the light combination. `{theme:'DARK', …}` builds a mode that a later lookup cannot find.
   - Where: `resolver.ts:343, 385-393`.
5. **Prototype keys.**
   - `setToken('__proto__.x')` pollutes `Object.prototype`.
   - `constructor.x` writes onto the global `Object`.
   - A token named `toString` cannot be stored.
   - A `"__proto__"` group in JSON vanishes.
   - Where: `src/core/collection.ts:439-455, 566, 877`.
6. **Immutability breaches.**
   - `resolve()` returns objects shared with the document, so mutating one changes every later `resolve()`.
   - `$extensions` is kept by reference.
   - `getToken().$value` can be changed in place.
7. **A W3C JSON Pointer `$ref` as a token value is skipped at load and never resolved.**
   - A number token returns the raw `{$ref}` object, with no error.
   - `$ref` is listed as future work, but passing it through silently breaks "failures are errors".
8. **`cssPropertyName` makes invalid names, and makes collisions.**
   - Invalid: `--opacity-50%`, `--size-1/2`.
   - Collisions, silent and unreported: `a.b` and `a-b`, and `bgColor` and `bg-color`. `cssLinkName` does escape.
   - Where: `src/utils/css-name.ts:15-38`.
9. **A set whose sources point to itself crashes.** The error is `Maximum call stack size exceeded`, not a named error. `load()` catches the case; `Resolver` does not.
10. **Gradient stop positions outside 0 to 1 are refused.** W3C says to clamp them. A test locks the refusal in.
11. **`fontFamily` has no load gate.**
    - `[1,{}]`, `''` and `[]` are all stored.
    - A family that refers to a stack nests arrays.
12. **`transparent` is stored with an 8-digit hex.** W3C requires 6 digits. The choice is deliberate and documented, but an adapter writing DTCG emits invalid output.
13. **The docs call removed APIs.**
    - The guide's first example calls `accent.set(...)`, which throws.
    - JSDoc still names `setDefaultMode`, `Resolver.step` and `collection.getModifiers`.
    - `reference.md` says `getToken` takes `'default'`, but it throws on a light/dark collection.
    - The nine-questions table omits `getLightDark` and `literalText`.
14. **Tests.**
    - The resolver tests never use the structured shapes: 0 `colorSpace` and 79 hex strings. That is the pattern the constitution forbids, and it is how items 1 and 3 hid.
    - The factoring property test still never asserts `checked`. 16.5% of its cells skip the comparison silently.
15. **Nits.**
    - There are two stray `.test.d.ts` files.
    - `setToken` accepts empty segments.
    - `getGroupAttribute` ignores the mode for plain attributes.

## gosfuig

Several things held:

- The colour conversions match an independent oracle to 6 decimals.
- The gamut clamp keeps L and H exactly.
- WCAG and APCA match the reference values.
- The contract is the documented 4.5:1.

1. **A gray, black or white pinned colour drags the ramp's hue to 0°.**
   - Example: blue at hue 259 with a pin at `#111111` on 950. Step 500 comes out `#85599b`, purple.
   - The note then blames the pin: "pulls the ramp hue by +101°".
   - Cause: an achromatic colour has no hue, and `h ?? 0` gives it 0 (`src/family.ts:279, 290`, `src/color/oklch.ts:32`).
2. **`seedFamily` from a gray seed goes wrong.**
   - It computes a negative chroma peak, which the package's own validator refuses. The studio therefore saves a config it cannot load.
   - The default chroma floors tint the ends pink: 50 comes out `#f1dce2` and 950 `#220611`.
3. **A light, vivid seed on a light step gets an absurd peak.** `#fde047` on step 50 gives peak 2.556, and 10 of 12 steps are clamped (`src/curves.ts:106`).
4. **Step collisions pass validation, and one colour is silently dropped.** Examples: a colour and a lock on one step, or one step named both by name and by index. The README says they are "refused outright".
5. **`wcag()` does not gamut-map a string input; `apca()` does.** For an out-of-gamut input, `evaluate()` can pass AA on a colour that fails once displayed: 4.60 against 4.32.
6. **DTCG export.**
   - A `.` separator makes dotted names, and a test asserts it.
   - A name starting with `$` is emitted as a key.
   - A hue can be rounded to exactly 360.
   - `colorSpace: 'srgb'` emits a bare hex string, not the 2025 object form.
7. **92 or more steps make duplicate names,** and tokens are overwritten silently.
8. **Alpha is silently discarded.**
9. **README drift.**
   - The cyan example's numbers are wrong.
   - It says templates have five fields where there are six.
   - It says `slug: "none"` strips characters, where it replaces them.
   - It says `check` runs typecheck and test, where it also runs eslint.
10. **Packaging.**
    - Two font packages are runtime dependencies used only by the unshipped studio.
    - There is no `require` condition.
11. **Tests.** Conversions are checked only for black and white and by round trips, and APCA only for sign. There are no reference values.
12. **The unpushed commit untracks CLAUDE.md.** It also adds no `.codegraph/` entry, despite its message.
